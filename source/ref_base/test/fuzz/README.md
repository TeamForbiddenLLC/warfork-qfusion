# BSP loader fuzzing

`.bsp` files are attacker-controlled. A client downloads the map from whatever
server it connects to, and a dedicated server loads whatever is installed. The
same file is then parsed twice by two independent sets of lump readers:

| target | parser | runs on |
|---|---|---|
| `r_q3bsp_fuzz` | `source/ref_base/r_q3bsp.c` (`Mod_LoadQ3BrushModel`) | client |
| `cm_q3bsp_fuzz` | `source/qcommon/cm_q3bsp.c` (`CM_LoadQ3BrushModel`) | client and dedicated server |

Both harnesses stub out their surrounding module (renderer / engine) and call
the loader directly on raw bytes.

**A rejected map is a pass.** Malformed input is supposed to exit through
`Com_Error(ERR_DROP, ...)`, which the harness catches with `longjmp` exactly as
the real client does. Only a crash, a sanitizer report, or a hang is a finding.

## Running

libFuzzer build (clang only):

```sh
cmake -S source -B build-fuzz -DBUILD_FUZZ_TEST=ON \
      -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++
cmake --build build-fuzz --target r_q3bsp_fuzz cm_q3bsp_fuzz

./build-fuzz/warfork-qfusion/test/r_q3bsp_fuzz.x86_64 \
    source/ref_base/test/fuzz/corpus -max_total_time=600 -max_len=65536
```

Replay build — no clang needed, runs the checked-in corpus once and exits
non-zero on failure. This is what CI executes as part of the normal
`./test/*` sweep:

```sh
cmake -S source -B build -DBUILD_UNIT_TEST=ON -DENABLE_SANITIZERS=ON
cmake --build build --target r_q3bsp_fuzz_test cm_q3bsp_fuzz_test
./build/warfork-qfusion/test/r_q3bsp_fuzz_test.x86_64
```

Either binary also accepts explicit paths, which is the quickest way to check a
real map still loads:

```sh
./r_q3bsp_fuzz_test.x86_64 assets/data1_21pure/maps/*.bsp
FUZZ_VERBOSE=1 ./r_q3bsp_fuzz_test.x86_64 some.bsp   # print the rejection reason
```

## Corpus

`corpus/seed_{ibsp,rbsp,fbsp}.bsp` are generated by `gen_seed.c`, built as the
`gen_bsp_seed` target. They are minimal but structurally valid: one of each face
type, a patch, a fog volume, and a small BSP tree, in each of the three
Q3-family formats `qcommon/bsp.c` accepts. Regenerate them after changing the
on-disk structs in `qcommon/qfiles.h`:

```sh
./build/warfork-qfusion/test/gen_bsp_seed.x86_64 source/ref_base/test/fuzz/corpus
```

Real maps are not used as seeds: the smallest in the repo is 6 MB, far too large
to mutate usefully. They are still worth replaying explicitly, as above.

`corpus/regress/` holds inputs that once crashed a loader. They are shared
between both targets — it is the same file format, and a crasher for one parser
is worth replaying through the other.
